# Mazzy Law PLLC — website

Static website for Mazzy Law PLLC. Plain HTML, CSS and a little JavaScript, generated by a
small build script with **no dependencies** (Node 18+ only, nothing to install).

- **Live site:** https://mazzylaw.com/ (hosted on Bluehost; open to search engines)
- **Preview:** https://karamathalip.github.io/mazzy-law/ (GitHub Pages; never indexed)

## Palette and typography

- **Palette:** the site uses the light-blue palette (`theme.default: "blue"` in
  `src/data/site.json`). The light-grey/gold variant is still defined in `src/assets/css/tokens.css`;
  set `theme.default` to `"grey"` to switch back.
  While `theme.showSwitcher` is `false` the palette is locked: `?theme=` links and any choice a
  visitor made during the preview are ignored. Set it to `true` to bring back the palette switch.
- **Typography:** Times New Roman throughout (a system font, so nothing is downloaded). Body text
  is 12 pt; paragraph titles are 13–14 pt bold. Only the page titles and the home-page headline
  are larger. All sizes are set in `src/assets/css/tokens.css`.

## Run it locally

```bash
node build.mjs          # writes ./dist
node build.mjs --serve  # builds and serves http://localhost:4173/
```

## Common edits

### Change text

Edit the JSON files in `src/data/`. No HTML knowledge is needed. Wrap words in `**double
asterisks**` to make them bold. Then run `node deploy.mjs`.

### Add a page

1. Copy `src/pages/disclaimers.mjs` to `src/pages/<name>.mjs` and change `id`, `path`
   (for example `'insights/'`), `title`, `description` and the `render()` body.
2. To show it in the menu, add one line to `nav` in `src/data/site.json`:
   `{ "label": "Insights", "path": "insights/" }`.

The header, footer, palettes and SEO tags apply automatically.

### Add contact details that are not yet supplied

In `src/data/site.json` fill in `email`. It appears on the Contact page and in the footer as soon
as it is non-empty. Nothing is shown while it is blank.

### Change the attorney photo

The portrait is `src/assets/img/m-mazzy.jpg` (square, 800×800 px). Replace the file, or point
`"photo"` in `src/data/attorney.json` at a new one.

### Contact form

Messages from the Contact page are delivered by [Web3Forms](https://web3forms.com) to
mmazzy@mazzylaw.com. The settings are under `contactForm` in `src/data/site.json`:

- `accessKey`: the Web3Forms access key for the receiving inbox. Web3Forms designed it to be
  public, so it can sit in the page source.
- `subject`: the subject line of each message.
- **Changing the receiving address:** request a new key for the new address at web3forms.com and
  put it in `accessKey`.
- **Other services:** `"provider": "formsubmit"` with `"to"`, or `"provider": "formspree"` with
  `"formId"`, are also supported.

If the background send fails, the form falls back to a normal page submission so the message is
still delivered.

### Replace the home-page photographs

The home page uses two photographs published on Unsplash under the
[Unsplash License](https://unsplash.com/license) (free for commercial use, no attribution
required), loaded from Unsplash's image CDN:

- Hero: Midtown Manhattan at dusk by Michael Discenza (`hero` in `src/data/site.json`).
- Mission & Values: the Lower Manhattan skyline with One World Trade Center, seen from Liberty
  Island, by Massimiliano Morosinotto (`mission`).

To self-host it or use a different picture:

1. Save the image in `src/assets/img/` (hero: landscape, about 2400 px wide; mission: landscape
   4:3, about 1200 px wide; each under 400 KB).
2. In the `hero` or `mission` block of `src/data/site.json` set `"image"` to its path (for
   example `"assets/img/hero-nyc.jpg"`) and `"imageIsUnsplash": false`, and update `alt`,
   `credit` and `creditUrl`.

If a photograph ever fails to load, the hero falls back to a solid dark background and the
mission section simply shows its text.

## Deployment

The site is built twice from the same source:

| Target | Command | Settings | Branch |
| --- | --- | --- | --- |
| Live site, https://mazzylaw.com/ | `node build.mjs` | `seo` in `src/data/site.json` | `live` |
| Preview, GitHub Pages | `node build.mjs --target=github` | `seo.targets.github` | `gh-pages` |

```bash
git add -A && git commit -m "Describe the change" && git push   # save the source
node deploy.mjs                                                 # build both, push both branches
```

`deploy.mjs` builds each target, commits it with a separate temporary index (your working files
and branch are untouched) and force-pushes it to its branch. GitHub Pages then updates the
preview by itself. It leaves `dist/` holding the live build.

### Bluehost (mazzylaw.com)

- The site's files live in `public_html/mazzylaw` on the Bluehost plan (cPanel).
- To update it, copy the contents of `dist/` (after `node deploy.mjs` or a plain
  `node build.mjs`) into `public_html/mazzylaw`, replacing what is there. In cPanel's File
  Manager: upload a zip of `dist/` and choose Extract. Hidden files must be included
  (`.htaccess`).
- `.htaccess` sets the custom 404 page and caching, and sends `noindex` to every host name
  other than mazzylaw.com, so Bluehost's temporary address is never indexed.
- DNS stays at GoDaddy, because the firm's email (Microsoft 365) is configured there. Only the
  website records point at Bluehost (`A @` and `www`). Never change the nameservers or the MX,
  autodiscover, SPF, DKIM or verification records.

### Optional: deploy the preview automatically on every push

`docs/github-actions-deploy.yml` is a ready-made GitHub Actions workflow that builds and
publishes the GitHub Pages preview whenever `main` changes. To turn it on, copy it to
`.github/workflows/deploy.yml` and push.
